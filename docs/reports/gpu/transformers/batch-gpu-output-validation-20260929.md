# Transformers GPU batch 동시 출력 검증

RTX 2060 SUPER에서 실제 `HuggingFaceTB/SmolLM2-135M-Instruct` 모델과 `transformers-enhanced-batch-gpu:0.1.1` 이미지를 사용했다. 서버는 `float16`, `max-parallel=4`, `batch-wait-ms=5`로 실행했다. 기준 출력은 같은 모델과 GPU dtype을 사용하는 Transformers base 엔진에서 생성했다.

길이가 다른 입력 16개를 동시에 서버 API로 보냈다. 출력 제한은 8, 16, 24, 32토큰을 반복했고, `temperature=0`을 사용했다. `ignore_eos=true`를 두 차례, `false`를 한 차례 실행했다. 각 차례의 요청 절반은 SSE 스트리밍을 사용했다.

| 확인 항목 | 결과 |
| --- | ---: |
| 완료한 요청 | 48 / 48 |
| 비어 있지 않은 출력 | 48 / 48 |
| SSE 정상 종료 | 24 / 24 |
| 기준 출력과 텍스트 완전 일치 | 47 / 48 |
| 기준 출력과 토큰 사용량, 종료 사유 일치 | 48 / 48 |

텍스트가 달랐던 1개는 정원에 관한 응답에서 `small, low-maintenance garden` 대신 `simple, low-maintenance garden`을 출력했다. 두 응답 모두 질문에 맞는 문장이며 완료 토큰 수는 같았다. 같은 `float16` 모델의 다른 프롬프트에서는 첫 토큰 후보 로그잇이 30.8125와 30.796875로 매우 가까웠고, 배치 폭과 KV 캐시 방식에 따라 선택이 달라지는 것을 확인했다. 따라서 `float16`에서 기본 엔진과 문자열이 항상 완전히 일치한다고 보장할 수 없다.

추가로 GPU `float32`에서 실제 모델의 기본 엔진과 배치 엔진을 직접 비교했다. 길이가 다른 입력 16개를 동시에 보내는 위 세 조건에서 48개 결과 모두 텍스트, 종료 사유와 토큰 수가 일치했고 스트리밍 조각도 완성 응답과 일치했다. 이 검증은 배치 작업자와 CUDA Graph의 결과 일치를 확인하며, 운영 설정인 `float16`의 문자열 완전 일치를 뜻하지는 않는다.
